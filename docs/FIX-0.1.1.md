# 0.1.1：框选无响应与授权提示修复

日期：2026-11-02。

用户反馈框选后无控制条，菜单中的“开始录制当前选区”始终禁用，系统也未显示授权提示。

## 修复

- 框选刚开始时，矩形从零尺寸逐渐增大。原实现直接将矩形向内缩 6 点，尺寸不足时 CoreGraphics 返回 `CGRect.null`，其原点为无穷值。将它传给 `addCursorRect` 会触发 AppKit 的 `NSInternalInconsistencyException`，中断框选。现在只登记有限且有面积的光标区域。
- 明确禁止把区域拖动当成窗口拖动；框选面板保持显示，并在这次框选期间获取键盘和主窗口焦点。
- 保存显示器 ID、坐标和缩放比例的值快照，避免回调依赖弱引用的 NSScreen。
- 从菜单栏发起框选时先结束菜单跟踪，再显示框选面板。
- 在进入框选之前检查、申请屏幕权限。权限尚未生效时，显示明确说明和系统设置入口；设置窗口也可检查和申请权限。
- 打包时先生成并签名新的应用，再替换应用目录，避免原地覆盖仍在运行的可执行文件。已经运行的旧版需要退出并重新打开才能使用修复。

## 验证

- 23 项测试通过：原有 14 项，加上 9 项区域交互和授权测试。包括初次拖动的零尺寸、小于 12 点选区、按下/拖动/松开、选区移动、未生效授权和已授权免重复申请。
- 使用生产代码的 `RegionSelector` 进行真实鼠标测试，拖动得到 900 × 500 像素选区，显示器 ID 1；控制条矩形与选区不相交，检查结果 `toolbarOutside: true`。
- 从真实复现中取得的 AppKit 堆栈明确指向 `SelectionView.resetCursorRects → addCursorRect`。修复后完成真实拖选，未再出现该异常。
- 检查工具只显示选择层，不采集屏幕内容，也没有替用户授予系统权限。

实际录屏、系统音频与不同显示器组合仍需在用户授权后验证。
